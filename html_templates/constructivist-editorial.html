01 // Context
The Weight Matrix
Problem

Every deep network is an act of compression. You take the vast, high-dimensional structure of the world and force it through increasingly narrow bottlenecks until you arrive at something your loss function will accept. The weight matrix is the instrument of this coercion.

What Rosenblatt understood in 1958 and what every subsequent architecture has elaborated on: the network does not learn facts. It learns transformations. The distinction is not philosophical -- it is the entire engineering constraint.

This distinction matters when you ask why a model fails. It does not fail because it lacks information. It fails because its transformations are miscalibrated to the manifold of data it was asked to compress.

Attention Is
Selection

Self-attention does not read the sequence. It votes on which parts of the sequence to attend to, then reweights the representation accordingly. The query, key, value decomposition is a learned routing system.

04 // In Practice
Implementation
Decisions

Production transformer deployment is not the model. It is the model plus the decisions made around it: quantization strategy, KV cache budget, batching logic, position encoding scheme. The architecture is a small fraction of what determines observed behavior.

The failure is rarely in the weights. It lives in the space between what the model was trained to do and what you are asking it to do.

Flash Attention resolves the memory bottleneck by reordering the matrix operations to exploit SRAM locality. The math is identical. The implementation is not. This is the kind of insight that cannot be derived from the paper alone -- it requires understanding the memory hierarchy of the hardware the model runs on.

model = AutoModelForCausalLM.from_pretrained(ckpt, attn_implementation="flash_attention_2")
// requires transformers >= 4.36 and flash-attn >= 2.0
