SITOR (SImplex Teleprinting Over Radio) is a maritime and military radioteletype mode built on CCIR 476, a 7-bit character code with an unusual property: every single valid character has exactly 4 mark (1) bits and 3 space (0) bits, no more, no less. That single design decision is the whole error-detection scheme - no separate checksum, no CRC, just a constant-weight code where a corrupted character almost always announces itself. Of the 128 possible 7-bit patterns, exactly 35 - the ones with exactly four 1-bits - are legal CCIR 476 characters (26 letters plus figures and control codes share these 35 patterns via a letter-shift/figure-shift split, the same trick Baudot/ITA2 uses). A receiver doesn't need to know what a character means to know it arrived broken - it just counts bits.

Flipping any single one of this codeword's 7 bits was checked in Python against all 7 positions: every flip changes the mark count to 3 or 5, never leaving it at 4 - so a lone bit error can never silently masquerade as a different valid character. This example demonstrates the mechanism; it isn't claimed to be a specific letter's real assigned code, since a full verified 35-entry CCIR 476 table wasn't available at the confidence bar this site holds itself to.
SITOR-Apoint-to-point, has a return channelSITOR-Bbroadcast, one-way only

The constant-ratio code is shared by both modes - what differs is what happens when a character arrives broken, which depends entirely on whether anyone's listening for a reply.

modelink shapeerror handling
SITOR-A (ARQ)two stations, a real back-channelthe receiver detects a bad codeword (wrong mark count) and asks the sender to repeat it - true automatic repeat request, the same idea TCP retransmission is built on, decades earlier and far simpler.
SITOR-B (FEC)one transmitter, arbitrarily many receivers (e.g. a coast station broadcasting weather or distress traffic to every ship in range)no receiver can ask for a repeat without every other receiver hearing the request too - so instead every character is simply sent twice, time-diversity-spaced, and a receiver that catches a valid copy on either transmission uses it.
same problem AX.25 packet radio solved differently decades later. Both are "what do we do when the return channel doesn't exist or doesn't scale" problems - SITOR-B's answer is brute-force duplication; modern forward-error-correcting codes (Reed-Solomon, LDPC) solve the same problem with far less bandwidth overhead, but SITOR-B predates the hardware needed to decode them in real time on 1960s equipment.

SITOR's career mirrors POCSAG's: built for a specific, demanding niche (ship-to-shore telex over HF radio, where fading and noise are constant), then largely displaced once satellites made a always-on data path to a ship both possible and dramatically less noisy.

1950s-60sCCIR 476 developed for maritime and military HF radioteletypethe constant-ratio code this page diagrams, designed specifically to survive noisy, fading shortwave paths without a checksum.
1970s-80sSITOR becomes standard equipment on commercial and naval vesselsship-to-shore telex, weather broadcasts, and distress traffic all rode this one mode.
1980samateur radio operators adapt the same constant-ratio idea into AMTORthe technique outlived its original maritime-only licensing - amateur radio still uses a close relative of this exact code today.
1990s-2000sGMDSS (Global Maritime Distress and Safety System) phases in satellite (Inmarsat) and digital selective callinga satellite link doesn't fight HF fading at all, making SITOR's noise-tolerant design less necessary for the safety-critical traffic it was built for.
