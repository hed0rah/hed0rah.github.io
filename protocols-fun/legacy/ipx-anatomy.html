IPX (Internetwork Packet Exchange) was Novell NetWare's network-layer protocol from 1983 until TCP/IP took over as NetWare's default in the late 1990s - a direct descendant of Xerox's XNS with the header format barely changed. Every address is 12 bytes: a 4-byte network number, a 6-byte node number (usually a MAC address), and a 2-byte socket - IPX had no separate ARP-equivalent because the node number already was the hardware address. A workstation's NetWare Core Protocol request: fixed IPX header, client socket 0x4003 talking to the server's well-known NCP socket 0x0451, both nodes on the same IPX network number.

IPX header (30 bytes)
no fragmentation, no checksum, no problem (mostly). IPX simply never defines a checksum algorithm - every packet ships with this field hardcoded to 0xFFFF, and error detection is left entirely to the link layer (Ethernet's own FCS). On Ethernet II framing, IPX gets its own EtherType, 0x8137 - see the Ethernet anatomy page's EtherType tab for where that sits next to 0x0800 and 0x86DD.

IPX's header is almost a direct copy of Xerox's 1980 XNS Internet Datagram Protocol - Novell changed little beyond the name. Its decline tracks the internet's rise almost exactly.

eraeventwhy it mattered
1980Xerox Network Systems (XNS) defines the Internet Datagram ProtocolIPX's header - checksum, length, transport control, packet type, 12-byte addresses - is this format almost unchanged.
1983Novell ships NetWare with IPX/SPX as its native stackIPX became the dominant LAN protocol of the DOS/Windows-3.1 era, well before TCP/IP was common on desktops.
1990sSAP and RIP broadcasts every 60 seconds, on every segment, by every serverIPX's chatty service-discovery model didn't scale past a campus network - one of the concrete reasons administrators pushed to replace it.
1998NetWare 5.0 makes IP the native protocol, IPX optionalthe same year Novell's own flagship OS stopped requiring IPX at all.
2000sWindows Vista (2007) and NetWare 6.5's later service packs drop IPX support entirelyIPX support was removed from mainstream operating systems - functionally dead outside emulation and retrocomputing.
why it lost. IPX addresses aren't globally assigned or hierarchical the way IP addresses are - a network number is just whatever the local administrator picked, which works fine on one campus and not at all across the open internet. TCP/IP's global addressing and routing won by being the only stack built for a network of networks, not just a network.
