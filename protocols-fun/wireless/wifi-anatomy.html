Every 802.11 frame - management, control, or data - opens with the same shaped MAC header, unchanged in its basics since the original 1997 standard. What makes it more interesting than Ethernet's header is the Frame Control field's ToDS/FromDS bit pair, which silently changes what the following address fields even mean - and the total absence of any authentication on most management frames, which is exactly what makes deauthentication attacks possible. The Frame Control field is the first thing decoded in every 802.11 frame - Type picks one of 3 frame classes (management, control, data), Subtype picks the specific frame within that class, and the remaining bits are mostly housekeeping flags. Shown here with a beacon's actual Frame Control bytes.

the same 6 bytes, four different jobs. Unlike Ethernet, where a frame always has exactly one destination and one source MAC, an 802.11 frame's three (or four) address fields are reinterpreted based on 2 bits elsewhere in the header - the wireless link has to separately track the immediate over-the-air receiver, the eventual destination, and the access point relaying between them.

The frame that announces a network exists. Broadcast to everyone (Addr1 = ff:ff:ff:ff:ff:ff), unencrypted even on a WPA2/WPA3 network (a device has to be able to read it before it's associated with anything), and sent roughly ten times a second whether or not anyone's listening.

this is how "hidden" networks aren't really hidden. An AP can omit its SSID from the beacon's SSID element (sending a zero-length one instead), but it still has to answer Probe Request frames from clients that already know the name - and those requests and responses go out in the clear too. "Hidden" SSID hides the network from casual scanning, not from anyone actually watching the air.

A management frame telling a station "you are no longer authenticated, start over." In the original standard, management frames carry no cryptographic protection at all - anyone in radio range can forge one with the right source and destination addresses.

deauthentication frame (26 bytes)
the deauth attack, in one sentence. Because a pre-802.11w deauth frame has no signature tying it to the real AP, an attacker who knows the AP's and target's MAC addresses (both broadcast in the clear in every data frame) can forge one and knock the target off the network at will - the basis of most Wi-Fi deauthentication attacks and a common step before a WPA handshake capture. 802.11w (Management Frame Protection, mandatory in WPA3) fixes this by adding a MIC to management frames, the same way WPA2 already protected data frames.

The MAC header this page diagrams has barely moved across 25+ years; nearly every meaningful revision to Wi-Fi has happened one layer up, in how the frame body gets encrypted and authenticated.

yearstandardwhat changed
1997802.11, WEP encryptionRC4 stream cipher with a static key and a 24-bit IV - the IV space was small enough that key reuse (and full key recovery) was practical within hours by 2001.
2003WPA (Wi-Fi Protected Access)an interim fix using TKIP - per-packet key mixing on top of the same RC4 cipher, deployed via firmware updates to WEP-era hardware while 802.11i finished.
2004WPA2 (802.11i)AES-CCMP replaces RC4/TKIP entirely - genuinely strong encryption, and the default for most Wi-Fi networks for the next 15 years.
2017KRACK (Key Reinstallation Attack) discloseda flaw in the WPA2 4-way handshake itself, not the cipher - a forced retransmission could trick a client into reinstalling an already-used key, exposed on both APs and clients until patched.
2018WPA3SAE (Simultaneous Authentication of Equals) replaces the WPA2 handshake's vulnerable pattern, and 802.11w Management Frame Protection becomes mandatory - the deauth attack shown on this page's previous tab stops working against a fully WPA3 client and AP.
