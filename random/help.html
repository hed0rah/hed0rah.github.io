Windows Triage: Malware and Slowness

Elevated PowerShell required: Win+X, then A. The title bar must read Administrator. Commands are read-only unless the block header says writes changes.

Start here

Before touching anything

  1. Back up the user profile first. Every step after this one can destroy evidence or data. The command is below.
  2. Do not download tools on the affected machine. A modified proxy, DNS or hosts file changes what a download returns. Carry the kit on a USB stick (see Tools & kit).
  3. Change one thing at a time and note what you changed. When the machine is fixed you want to know which step did it; when it is not, you want to know what to undo.
  4. Read on the phone, type on the PC. Every command block has a copy link; it is easier to read this page on a phone than to alt-tab on the machine you are fixing.

Back up the user profile

robocopy[copy]
robocopy "$env:USERPROFILE" "D:\rescue" /E /R:1 /W:1 /XJ /XA:SH

Change D:\rescue to the stick or external drive. /XJ prevents junction loops. Format the target exFAT; FAT32 fails silently over 4 GB. Copying from a Linux live stick is safer where practical, because nothing on the sick disk runs.

Open an elevated PowerShell

Win+X, then A. Or: right-click Start, choose Terminal (Admin) or Windows PowerShell (Admin). Accept the prompt. If the account cannot elevate, it is not an administrator; log in as one. The window title must say Administrator or half the commands below return nothing useful.

The five-minute snapshot

One paste. Prints what the machine is and what state it is in. Save the output and send it to whoever is helping remotely: this block answers most of their first questions.

snapshot: paste as one block[copy]
$os=gcim Win32_OperatingSystem; $cs=gcim Win32_ComputerSystem; $cpu=gcim Win32_Processor
"=== $($cs.Manufacturer) $($cs.Model)"
"OS      : $($os.Caption) build $($os.BuildNumber)"
"Uptime  : $([int]((Get-Date)-$os.LastBootUpTime).TotalHours) h since last real boot"
"CPU     : $($cpu.Name)  cores=$($cpu.NumberOfCores) load=$($cpu.LoadPercentage)%"
"RAM     : total $([math]::Round($os.TotalVisibleMemorySize/1MB,1)) GB, free $([math]::Round($os.FreePhysicalMemory/1MB,1)) GB"
"Power   : $(powercfg /getactivescheme)"
"FastBoot: HiberbootEnabled=$((Get-ItemProperty 'HKLM:\SYSTEM\CurrentControlSet\Control\Session Manager\Power').HiberbootEnabled)"
"--- disks"
Get-PhysicalDisk | Select FriendlyName,MediaType,HealthStatus,@{n='GB';e={[math]::Round($_.Size/1GB)}} | Format-Table -AutoSize
Get-Volume | ? DriveLetter | Select DriveLetter,FileSystemType,@{n='FreeGB';e={[math]::Round($_.SizeRemaining/1GB,1)}},@{n='SizeGB';e={[math]::Round($_.Size/1GB,1)}} | Format-Table -AutoSize
"--- security products"
Get-CimInstance -Namespace root\SecurityCenter2 -ClassName AntiVirusProduct | Select displayName | Format-Table -AutoSize
Get-MpComputerStatus | Select AMRunningMode,RealTimeProtectionEnabled,AntivirusSignatureLastUpdated | Format-List
"--- last 3 updates"
Get-HotFix | Sort InstalledOn -Desc | Select -First 3 HotFixID,InstalledOn | Format-Table -AutoSize

To save it: append | Out-File "$env:USERPROFILE\Desktop\snapshot.txt" is awkward across many lines, so instead press Ctrl+A then Ctrl+C in the terminal and paste into a message, or photograph the screen.

How to read it

  • Uptime in the hundreds of hours on a machine that is "shut down every night": Fast Startup is on (HiberbootEnabled=1), so shutdown is a hibernate and the machine has not actually rebooted in weeks. shutdown /r /t 0 does a real restart. This alone fixes a surprising amount.
  • MediaType HDD on the system disk: the machine is slow because it is a spinning disk running a modern Windows. Nothing in software fixes that; an SSD does. See Slowness.
  • HealthStatus anything but Healthy: back up now, replace the disk.
  • FreeGB under 10% of the system volume, or under 15 GB: Windows itself stalls. Free space before anything else.
  • Two security products listed, or RealTimeProtectionEnabled : False: go to Malware & cleanup. Two resident antivirus engines is a common cause of both slowness and "the antivirus keeps popping up".
  • RAM total 4 GB: a browser alone fills it. See the memory section under Slowness.
  • Power plan "Power saver", or a laptop that is always on battery: expect throttled clocks. See CPU and thermal under Slowness.

Malware & cleanup

Detect remote access software

Get-Process / Get-Service[copy]
$rat='anydesk|teamviewer|logmein|screenconnect|connectwise|supremo|ultraviewer|ammyy|gotoassist|splashtop|remotepc|rustdesk|zoho|dwagent|atera|quickassist'
Get-Process | ? {$_.Name -match $rat} | Select Name,Path
Get-Service | ? {$_.Name -match $rat -or $_.DisplayName -match $rat} | Select Name,DisplayName,Status,StartType
Run first. These are legitimately signed commercial products, so antivirus does not flag them and they do not appear in malware scan results. A scammer who was "fixing the computer" usually leaves one installed, set to start with Windows, with unattended access enabled. Correlate any hit against the installed-programs list below: a service with no uninstall entry, or an install date inside the cluster identified there, indicates unattended deployment rather than deliberate installation. Uninstall it, then check the vendor's web console if the owner has an account (a scammer may have registered the machine to their own).

List installed programs by install date

Get-ItemProperty[copy]
$k='HKLM:\Software\Microsoft\Windows\CurrentVersion\Uninstall\*',
   'HKLM:\Software\WOW6432Node\Microsoft\Windows\CurrentVersion\Uninstall\*',
   'HKCU:\Software\Microsoft\Windows\CurrentVersion\Uninstall\*'
Get-ItemProperty $k | ? DisplayName | Select DisplayName,Publisher,InstallDate |
  Sort InstallDate -Desc | Format-Table -AutoSize

A group of installations sharing one date identifies the incident. Treat the whole group as suspect regardless of publisher name. Keep $k defined; the uninstall step below reuses it.

Report registered security products

SecurityCenter2 / Get-MpComputerStatus[copy]
Get-CimInstance -Namespace root\SecurityCenter2 -ClassName AntiVirusProduct |
  Select displayName,pathToSignedProductExe
Get-MpComputerStatus | Select AMRunningMode,RealTimeProtectionEnabled,AntivirusEnabled,AntivirusSignatureLastUpdated

RealTimeProtectionEnabled : False indicates Defender was disabled by another product. Two products listed means two resident engines fighting over every file.

Accounts and remote desktop

Get-LocalUser / Administrators / RDP[copy]
Get-LocalUser | Select Name,Enabled,LastLogon,PasswordLastSet | Format-Table -AutoSize
Get-LocalGroupMember Administrators | Select Name,PrincipalSource
(Get-ItemProperty 'HKLM:\SYSTEM\CurrentControlSet\Control\Terminal Server').fDenyTSConnections

Every enabled account should be one the owner recognises. An extra local administrator is a backdoor. fDenyTSConnections is 1 on a home machine; 0 means Remote Desktop is enabled, which almost no home user did on purpose.

Live network connections, by process

Get-NetTCPConnection[copy]
Get-NetTCPConnection -State Established | % {
  $p=Get-Process -Id $_.OwningProcess -EA 0
  [pscustomobject]@{Proc=$p.Name;Pid=$_.OwningProcess;Remote="$($_.RemoteAddress):$($_.RemotePort)";Path=$p.Path}
} | Sort Proc | Format-Table -AutoSize

Close the browser first so the list is short. Anything holding a connection from AppData, Temp or ProgramData deserves a look. A process with an empty Path is running as a different user or is protected; Process Explorer or System Informer will show it.

Running code that is not signed

Get-AuthenticodeSignature[copy]
Get-Process | ? Path | Select -Unique -Expand Path | % { Get-AuthenticodeSignature $_ } |
  ? Status -ne 'Valid' | Select Status,Path | Format-Table -AutoSize

Legitimate software is occasionally unsigned, so this is a shortlist, not a verdict. Anything unsigned and in a user-writable folder and not in the installed-programs list is the intersection that matters.

Enumerate persistence

Persistence is where malware and unwanted software survive a reboot. Check all four places; the task scheduler is used more often than the Run keys.

Run keys / StartupCommand / scheduled tasks[copy]
Get-ItemProperty 'HKLM:\Software\Microsoft\Windows\CurrentVersion\Run',
  'HKCU:\Software\Microsoft\Windows\CurrentVersion\Run',
  'HKLM:\Software\Microsoft\Windows\CurrentVersion\RunOnce',
  'HKCU:\Software\Microsoft\Windows\CurrentVersion\RunOnce' -EA 0 |
  Select * -Exclude PS* | Format-List
Get-CimInstance Win32_StartupCommand | Select Name,Command,Location | Format-List
Get-ScheduledTask | ? {$_.TaskPath -notlike '\Microsoft\*'} |
  Select State,TaskPath,TaskName,@{n='Run';e={$_.Actions.Execute + ' ' + $_.Actions.Arguments}} |
  Sort State | Format-Table -AutoSize
third-party services[copy]
Get-CimInstance Win32_Service | ? {$_.PathName -notmatch '\\Windows\\'} |
  Select Name,State,StartMode,PathName | Sort State | Format-Table -AutoSize
WMI event subscriptions (normally empty)[copy]
Get-CimInstance -Namespace root\subscription -ClassName __EventFilter | Select Name,Query
Get-CimInstance -Namespace root\subscription -ClassName CommandLineEventConsumer | Select Name,CommandLineTemplate
Get-CimInstance -Namespace root\subscription -ClassName __FilterToConsumerBinding | Select Filter,Consumer

WMI subscriptions run a command when a system event fires and survive most cleanups because nothing in the normal UI shows them. A home machine has none, or only Microsoft's own SCM Event Log entries. Anything else is a finding.

Browser: shortcuts, forced extensions, policies

WScript.Shell / ExtensionInstallForcelist[copy]
$w=New-Object -ComObject WScript.Shell
Get-ChildItem "$env:USERPROFILE\Desktop","$env:PUBLIC\Desktop","$env:APPDATA\Microsoft\Internet Explorer\Quick Launch\User Pinned\TaskBar" -Filter *.lnk -Recurse -EA 0 |
  % { $s=$w.CreateShortcut($_.FullName); [pscustomobject]@{Name=$_.Name;Target=$s.TargetPath;Args=$s.Arguments} } |
  ? {$_.Target -match 'chrome|msedge|firefox|brave|opera'} | Format-Table -AutoSize
Get-ItemProperty 'HKLM:\Software\Policies\Google\Chrome\ExtensionInstallForcelist',
  'HKLM:\Software\Policies\Microsoft\Edge\ExtensionInstallForcelist',
  'HKCU:\Software\Policies\Google\Chrome\ExtensionInstallForcelist' -EA 0 | Select * -Exclude PS*

Args must be empty for a normal browser shortcut. A URL or --load-extension= reinstates the hijack at every launch. ExtensionInstallForcelist must not exist on a home machine: it is the enterprise policy that installs an extension the user cannot remove, and it is how a "managed by your organization" banner appears on a family PC. Open chrome://policy or edge://policy to see every policy in force, and chrome://extensions to review what is installed.

Check proxy, DNS and hosts file

Internet Settings / DNS / hosts[copy]
Get-ItemProperty 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Internet Settings' |
  Select ProxyEnable,ProxyServer,AutoConfigURL
Get-DnsClientServerAddress -AddressFamily IPv4 | ? ServerAddresses |
  Select InterfaceAlias,ServerAddresses
Get-Content $env:WINDIR\System32\drivers\etc\hosts | ? {$_ -notmatch '^\s*#' -and $_.Trim()}

A populated AutoConfigURL is a hijack. DNS should be the router's address or a known public resolver, not an unfamiliar IP. The hosts file should return no output.

Reset proxy and DNS

writes changes[copy]
Remove-ItemProperty 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Internet Settings' -Name AutoConfigURL -EA 0
Set-ItemProperty 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Internet Settings' -Name ProxyEnable -Value 0
Set-DnsClientServerAddress -InterfaceAlias '<alias from above>' -ResetServerAddresses
ipconfig /flushdns

Find recently written executables

Get-ChildItem[copy]
Get-ChildItem $env:APPDATA,$env:LOCALAPPDATA,$env:ProgramData,$env:TEMP,"$env:USERPROFILE\Downloads" -Recurse -Include *.exe,*.dll,*.ps1,*.vbs,*.js,*.bat,*.scr -EA 0 |
  ? {$_.LastWriteTime -gt (Get-Date).AddDays(-60)} |
  Sort LastWriteTime -Desc | Select -First 40 LastWriteTime,Length,FullName

Adjust the 60 days to bracket the incident. Script files in Downloads or Temp with a recent date are as important as executables.

Retrieve an uninstall string

UninstallString[copy]
Get-ItemProperty $k | ? {$_.DisplayName -like '*partial name*'} | Select DisplayName,UninstallString,QuietUninstallString

Execute the returned string. MSI packages accept msiexec /x {GUID} /qn. Prefer the vendor's own uninstaller over deleting folders; a half-removed antivirus is worse than a whole one.

Re-enable Defender and scan

writes changes[copy]
Set-MpPreference -DisableRealtimeMonitoring $false
Update-MpSignature
Start-MpScan -ScanType QuickScan
Get-MpThreatDetection | Select -Last 20 ThreatID,InitialDetectionTime,Resources

If the quick scan finds anything, or the machine still misbehaves: Start-MpWDOScan reboots into Defender Offline, which scans before Windows and its rootkit-capable malware load. Save work first; it restarts immediately. Microsoft Safety Scanner (msert.exe, in the kit) is a second opinion that needs no install.

Confirm patch level

Get-HotFix[copy]
Get-HotFix | Sort InstalledOn -Desc | Select -First 5 HotFixID,Description,InstalledOn
Get-Service wuauserv,bits,TrustedInstaller | Select Name,Status,StartType

Months without an update means Windows Update is broken or disabled; both are worth fixing before handing the machine back.

Removal sequence

  1. Uninstall any remote access tool that the owner did not install.
  2. Uninstall the unwanted security product. It obstructs removal and commonly holds Defender disabled.
  3. Run AdwCleaner. Add a Malwarebytes on-demand scan if results are unclear.
  4. Run Autoruns with Options > Hide Microsoft entries. Review Logon, Scheduled Tasks, Services and WMI. Uncheck rather than delete; you can re-check if something breaks.
  5. Re-enable Defender, update signatures, quick scan. Offline scan if anything was found.
  6. Reset browser search engine, homepage and startup pages. Remove all extensions; restore an ad blocker only. Delete any forced-extension policy key found above.
  7. Remove extra accounts, disable Remote Desktop, reset proxy and DNS.
  8. Change passwords from a different device for anything used on this PC during the incident: email first, then banking. Turn on two-factor.
  9. Reboot, re-run the snapshot on the Start tab, compare.
If money moved, a bank was called, or a gift card was bought: this is fraud, not just malware. Contact the bank from a known-good phone number, not one from the screen or a call-back. Report it; the technical cleanup can wait an hour, the bank cannot.
Reinstalling the operating system discards the profile, the installed-program history and every persistence artifact above. Enumerate before considering it. If you do reset, Reset this PC > Remove everything is the only option that removes what a scammer left; "Keep my files" keeps their extensions and tasks too.

Slowness

Shape the problem first

"It's slow" is five different problems. Ten minutes of questions saves an afternoon of guessing. Ask, or watch:

Slow whenPoints atSection
Booting and the first ten minutes after loginstartup load, HDD, Windows catching up on updates and indexingDisk, Startup, Windows' own work
All the time, everythingHDD, full disk, too little RAM, or a second antivirusDisk, Memory
After 10 to 30 minutes, fans loudthermal throttlingCPU and heat
In bursts: hitches, audio crackle, cursor freezesDPC latency, a driver Stutter
Only in the browserextensions, tabs, hardware accelerationBrowser
Only online thingsthe network, not the PCNetwork vs PC
Since a specific dayan update, an install, or an incidentReliability Monitor below, then the Malware tab's install-date list
real uptime, and what changed recently[copy]
(Get-Date) - (gcim Win32_OperatingSystem).LastBootUpTime | Select Days,Hours
perfmon /rel

Reliability Monitor (perfmon /rel) opens a timeline of every crash, hang, failed update and install, by day. If the slowness "started last Tuesday", this is where Tuesday is. Look for a red X cluster or a new install on that date.

Reboot first, for real. With Fast Startup on, "Shut down" hibernates the kernel; the machine may not have rebooted in weeks and leaked memory and stuck services accumulate. shutdown /r /t 0 is a genuine restart. Re-test after it. A large share of "slow" reports end here.

Watch it live: Task Manager and Resource Monitor

Ctrl+Shift+Esc opens Task Manager. On the Processes tab, click the column headers to sort by CPU, Memory, Disk and Network in turn. The question is not "what is high" but "what is high while the user is doing nothing". Let it sit two minutes.

  • Disk at 100% with low CPU is the signature of a spinning disk that cannot keep up, or of a background job (indexing, updates, antivirus scan, OneDrive sync) saturating it. Sort by Disk to see who. See the Disk section.
  • Memory at 90%+ means Windows is paging to disk; on an HDD that is catastrophic. Sort by Memory. A browser with many tabs is the usual answer.
  • CPU pinned by one process: note its name and look it up. Pinned by "System" or "System interrupts": a driver; see Stutter.
  • The Startup apps tab lists what runs at login with a measured impact. Disable everything that is not antivirus, audio, or something the user opens daily. This is safe and reversible.

Resource Monitor (resmon) goes one level deeper: the Disk tab shows per-file activity and the Response Time (ms) column, and Memory shows the hard fault rate. Sustained disk response times over 50 ms, or hard faults in the hundreds per second, are the machine telling you it is I/O-bound.

Disk: the usual answer on an older machine

type, health, wear, free space[copy]
Get-PhysicalDisk | Select FriendlyName,MediaType,BusType,HealthStatus,@{n='GB';e={[math]::Round($_.Size/1GB)}} | Format-Table -AutoSize
Get-PhysicalDisk | Get-StorageReliabilityCounter | Select DeviceId,Wear,Temperature,ReadErrorsTotal,WriteErrorsTotal,PowerOnHours | Format-Table -AutoSize
Get-Volume | ? DriveLetter | Select DriveLetter,FileSystemType,HealthStatus,@{n='FreeGB';e={[math]::Round($_.SizeRemaining/1GB,1)}},@{n='SizeGB';e={[math]::Round($_.Size/1GB,1)}} | Format-Table -AutoSize
  • MediaType HDD as the system disk: this is the diagnosis. Windows 10 and 11 assume an SSD; on a spinning disk every login, update and antivirus scan competes for a hundred random reads a second. Cleaning helps at the margins. A 500 GB SATA SSD and a clone or reinstall turns a ten-year-old laptop into a usable machine. Nothing else on this page comes close.
  • HealthStatus not Healthy, ReadErrorsTotal climbing, or CrystalDiskInfo saying Caution: back up today, replace the disk. A failing disk retries reads for seconds at a time, which presents exactly as "randomly freezes".
  • Wear on an SSD is percent used; a value in the 90s means it is near end of life.
  • Free space under 10%, or under about 15 GB: Windows cannot update, cannot page, and the SSD cannot garbage-collect. Free space before anything else.
is the disk the bottleneck right now[copy]
Get-Counter '\PhysicalDisk(_Total)\Avg. Disk Queue Length','\PhysicalDisk(_Total)\% Disk Time','\PhysicalDisk(_Total)\Avg. Disk sec/Transfer' -SampleInterval 2 -MaxSamples 10 |
  % { $_.CounterSamples | Select Path,@{n='Value';e={[math]::Round($_.CookedValue,3)}} } | Format-Table -AutoSize

On an idle machine the queue length should sit under 1 and sec/Transfer under 0.02 (20 ms). Sustained queue over 2 with the user idle: something is hammering the disk; go to Task Manager, sort by Disk. Counter names are English-locale; on a non-English Windows use resmon instead.

what is taking the space[copy]
Get-ChildItem C:\ -Directory -Force -EA 0 | % { [pscustomobject]@{GB=[math]::Round((Get-ChildItem $_.FullName -Recurse -Force -EA 0 | Measure-Object Length -Sum).Sum/1GB,1);Dir=$_.FullName} } | Sort GB -Desc
Get-ChildItem "$env:USERPROFILE" -Directory -Force -EA 0 | % { [pscustomobject]@{GB=[math]::Round((Get-ChildItem $_.FullName -Recurse -Force -EA 0 | Measure-Object Length -Sum).Sum/1GB,1);Dir=$_.Name} } | Sort GB -Desc | Select -First 12

Slow on a big disk; let it run. Usual offenders: Downloads, a game library, a phone-photo dump, C:\Windows\Installer, an old Windows.old, and hiberfil.sys (the size of RAM). Settings > System > Storage > Cleanup recommendations handles the Windows side safely. cleanmgr with Clean up system files removes old update files and Windows.old.

writes changesrepair and optimise[copy]
chkdsk C: /scan
sfc /scannow
DISM /Online /Cleanup-Image /RestoreHealth
Optimize-Volume -DriveLetter C -Analyze -Verbose
Optimize-Volume -DriveLetter C -ReTrim -Verbose      # SSD
Optimize-Volume -DriveLetter C -Defrag -Verbose      # HDD only, and only if Analyze said so

chkdsk /scan runs online without a reboot and reports whether a repair is needed. sfc and DISM repair Windows' own files; run DISM first if sfc says it could not fix something, then sfc again. Scheduled optimisation is on by default (Optimize Drives app); if it shows "Never run", turn it back on. Never defragment an SSD; ReTrim is the SSD equivalent.

Memory

how much, how used, who[copy]
$os=gcim Win32_OperatingSystem
[pscustomobject]@{TotalGB=[math]::Round($os.TotalVisibleMemorySize/1MB,1);FreeGB=[math]::Round($os.FreePhysicalMemory/1MB,1)}
gcim Win32_PhysicalMemory | Select @{n='GB';e={$_.Capacity/1GB}},Speed,Manufacturer,DeviceLocator | Format-Table -AutoSize
gcim Win32_PageFileUsage | Select Name,AllocatedBaseSize,CurrentUsage,PeakUsage
Get-Process | Sort WS -Desc | Select -First 15 Name,Id,@{n='MB';e={[math]::Round($_.WS/1MB)}},@{n='CommitMB';e={[math]::Round($_.PM/1MB)}} | Format-Table -AutoSize
  • 4 GB total is not enough for current Windows plus a browser. 8 GB is the floor, 16 GB is comfortable. The DeviceLocator rows show how many slots are populated; one stick in a two-slot laptop means an upgrade is a ten-minute job.
  • PeakUsage on the page file near AllocatedBaseSize means the machine has been running out of RAM. On an HDD that is the "everything freezes when I switch windows" feeling.
  • Sum the browser's processes (chrome, msedge, firefox each spawn many). Twenty tabs on 8 GB is the whole problem more often than not. Fewer tabs, a tab-suspending extension, or the browser's own memory saver setting.
  • A single process growing over hours until a reboot fixes it is a leak. Note the name; update or replace that program. If nothing in the list accounts for used memory, the leak is in a driver: RAMMap (Sysinternals, in the kit) shows nonpaged pool, and poolmon from the Windows Driver Kit names the tag.

CPU, heat and power

clocks, load, plan, and who is burning it[copy]
gcim Win32_Processor | Select Name,NumberOfCores,NumberOfLogicalProcessors,MaxClockSpeed,CurrentClockSpeed,LoadPercentage
powercfg /getactivescheme
Get-Process | Sort CPU -Desc | Select -First 15 Name,Id,@{n='CPUsec';e={[math]::Round($_.CPU)}},StartTime | Format-Table -AutoSize
  • CurrentClockSpeed far below MaxClockSpeed under load is throttling. Two causes: heat, or power. Run HWiNFO (kit) with Sensors open: CPU package temperature at 95 to 100 °C and a "Thermal Throttling: Yes" flag means dust in the heatsink, a dead fan, or dried thermal paste. A laptop that gets slow after twenty minutes and has a hot underside is this. Compressed air through the vents is the first fix; a repaste is the second.
  • Power saver as the active plan, or a laptop that lives on battery, caps clocks. Balanced is right for almost everyone; High performance for a desktop that feels sluggish. In Settings, check Power mode is not "Best power efficiency" while plugged in.
  • CPUsec is total processor time since the process started. Something with a huge number and a StartTime of today has been burning a core all day. Common: a stuck updater, a cloud-sync client re-scanning, a second antivirus, a browser tab running a miner, an indexer that never finishes.
the built-in power and battery reports[copy]
powercfg /energy /output "$env:USERPROFILE\Desktop\energy.html" /duration 60
powercfg /batteryreport /output "$env:USERPROFILE\Desktop\battery.html"

The energy report traces for 60 seconds and lists processes that keep the CPU awake, devices that block sleep, and platform timer abuse. The battery report shows design versus current capacity: a battery at 40% of design makes a laptop throttle on battery even when charged.

Startup load and third-party services

what starts, what runs[copy]
Get-CimInstance Win32_StartupCommand | Select Name,Command,Location | Format-Table -AutoSize
Get-CimInstance Win32_Service | ? {$_.State -eq 'Running' -and $_.PathName -notmatch '\\Windows\\'} |
  Select Name,DisplayName,StartMode,PathName | Format-Table -AutoSize
Get-ScheduledTask | ? {$_.State -eq 'Ready' -and $_.TaskPath -notlike '\Microsoft\*'} | Select TaskPath,TaskName | Format-Table -AutoSize

The pattern on a family PC: an OEM updater or three (Dell SupportAssist, HP Support Assistant, Lenovo Vantage), a trial antivirus from the factory (McAfee, Norton), two game launchers, a printer suite, Spotify, Discord, a cloud sync client, and a driver-update utility nobody installed on purpose. Each is small; together they are the first five minutes after login. Disable at startup (Task Manager > Startup apps) rather than uninstall, unless the program itself is unwanted. Autoruns (kit) shows all of this in one window with a checkbox per entry and Hide Microsoft entries; it is the fastest tool for this job.

factory and Store bloat[copy]
Get-AppxPackage | Select Name,Publisher | Sort Name | Format-Table -AutoSize
Get-ItemProperty $k | ? DisplayName | Select DisplayName,Publisher | Sort Publisher | Format-Table -AutoSize

($k is defined on the Malware tab's installed-programs block.) Uninstall through Settings > Apps. A second antivirus is the single most valuable removal on this list; two resident engines scan every file twice and lock each other out.

Windows' own background work

the services that saturate a disk[copy]
Get-Service WSearch,SysMain,wuauserv,bits,TrustedInstaller,DoSvc,DiagTrack | Select Name,DisplayName,Status,StartType | Format-Table -AutoSize
Get-DeliveryOptimizationStatus -EA 0 | Select FileId,Status,BytesDownloaded | Select -First 5
Get-Process -Name SearchIndexer,TiWorker,MsMpEng,CompatTelRunner -EA 0 | Select Name,@{n='CPUsec';e={[math]::Round($_.CPU)}},@{n='MB';e={[math]::Round($_.WS/1MB)}}
  • SearchIndexer (WSearch) rebuilding its index after an update or a big file copy saturates an HDD for hours. Benign if it finishes. Settings > Search > Searching Windows shows indexing status; if it says "indexing in progress" for days, rebuild it from Advanced indexing options.
  • TiWorker (TrustedInstaller) is Windows Update installing. High disk for an hour after an update is normal; high disk for days means an update is stuck. Settings > Windows Update > Update history shows failures; the Windows Update troubleshooter fixes most.
  • MsMpEng is Defender scanning. A scheduled full scan on an HDD is a slow afternoon. Check Windows Security > Virus protection > Scan options is not stuck on a full scan. If a second antivirus is installed, Defender should be passive (AMRunningMode : Passive); if both are active, remove one.
  • SysMain (formerly Superfetch) preloads to RAM. Helps on HDDs, does nothing useful on SSDs, and on a few HDD machines causes constant disk activity; disabling it is a legitimate test, and reversible.
  • CompatTelRunner is telemetry; it runs and finishes. If it is always running, it is stuck.

Boot time: what Windows measured

Diagnostics-Performance log[copy]
Get-WinEvent -LogName 'Microsoft-Windows-Diagnostics-Performance/Operational' -MaxEvents 400 |
  ? {$_.Id -eq 100} | Select -First 10 TimeCreated,@{n='Boot';e={($_.Message -split "`n")[0]}}
Get-WinEvent -LogName 'Microsoft-Windows-Diagnostics-Performance/Operational' -MaxEvents 400 |
  ? {$_.Id -ge 101 -and $_.Id -le 110} | Select -First 25 TimeCreated,Id,@{n='Culprit';e={($_.Message -split "`n")[0]}} | Format-Table -Wrap

Windows times every boot. Event 100 carries the boot duration in its message: under 30 s is an SSD, 60 to 120 s is an HDD, and several minutes is a problem. Events 101 to 110 name what was slow: 101 an application, 102 a driver, 103 a service, 106 a background optimisation, 109 a device. The culprits named there are the startup list above, measured rather than guessed. A driver (102) or device (109) that repeats across boots is worth updating or removing.

Stutter, crackle and hitches: DPC latency

A fast machine that hitches, crackles audio, or freezes the cursor for a moment is usually not slow; a driver is holding the CPU in a deferred procedure call for too long. Task Manager shows this as System interrupts or System using CPU. The tool for it is LatencyMon (kit).

  1. Run LatencyMon as administrator, press the green start button, and use the machine normally for five to ten minutes, including whatever triggers the stutter.
  2. The Main tab gives a verdict. Highest reported DPC routine execution time under about 500 µs is fine; over 1000 µs (1 ms) will be audible and visible.
  3. The Drivers tab, sorted by Highest execution (ms), names the driver. The usual suspects and what they mean:

Per-process forensics: System Informer and Process Explorer

Task Manager answers "who is busy". These answer "why, and what is it touching".

System Informer (formerly Process Hacker 2; kit) run as administrator. What to use:

  • The process tree shows the real parent: a powershell.exe under winword.exe, or anything under a browser that is not the browser, is a finding. Task Manager hides this.
  • Right-click a process > Properties: the Disk and Network tabs show bytes per second for that one process, which Task Manager only totals. This is how you find the one thing hammering the disk when the total says 100%.
  • The Services tab maps each service to the svchost.exe hosting it, so a busy svchost stops being anonymous.
  • Colours: purple is a packed or compressed executable (common for malware, also some games), pink a service, light blue your own processes. Hover for the legend.
  • Terminate tree kills a process and everything it spawned, which is what you want for a browser hijack or a runaway installer.

Process Explorer (Sysinternals, kit) does most of the same and is Microsoft-signed, which matters when an antivirus objects to System Informer's kernel driver. Two features worth the download on their own: Options > Verify Image Signatures adds a column that says whether each running file is signed and by whom, and Options > VirusTotal.com > Check VirusTotal.com adds a detection ratio per process. A hash the world has never seen, unsigned, in AppData, is the malware-tab intersection again, now with numbers.

Browser

  • Shift+Esc in Chrome and Edge opens the browser's own task manager: per-tab and per-extension memory and CPU. Sort by CPU. One tab or one extension is usually the answer.
  • chrome://extensions, edge://extensions: remove everything the user cannot name. Coupon finders, "PDF converters", search assistants and weather bars are adware, and they run on every page.
  • Hardware acceleration: on for a good GPU, but on an old integrated GPU or a bad driver it causes stutter and tearing. Toggle it in Settings > System and restart the browser to test.
  • Memory saver / sleeping tabs (in the browser's Performance settings) frees RAM from background tabs. Turn it on for any machine with 8 GB or less.
  • Reset settings (Settings > Reset) restores search engine, homepage and startup pages and disables extensions without deleting bookmarks or passwords. Safe first move.

  • Ping to the router (second line) over 5 ms, or with drops, is a Wi-Fi problem, not a PC problem. Signal under 60% or a receive rate far below the link speed means move closer, change the channel, or use a cable.
  • DNS to 1.1.1.1 fast but the default resolver slow: the router's DNS, or a hijacked one (Malware tab).
  • Everything above fine but pages slow: run the browser section. Everything fine and one site slow: that site.
  • A cloud client (OneDrive, Google Drive, iCloud, Steam, a Windows update) saturating the uplink makes everything else feel slow; Task Manager sorted by Network shows it.

The fix ladder

In order of effort against payoff, once the diagnosis is in:

  1. Real reboot, and turn Fast Startup off if uptime was absurd.
  2. Free space to at least 15% of the system volume.
  3. Remove the second antivirus, and every startup entry that is not needed.
  4. Remove adware extensions, reset the browser, enable memory saver.
  5. Update: Windows, then the graphics and Wi-Fi drivers from the vendor, then BIOS if ACPI or throttling was implicated.
  6. Clean the vents, or repaste, if temperatures said so.
  7. SSD, if the system disk is an HDD. Clone with the SSD vendor's tool or reinstall. This is the step that changes the machine.
  8. RAM to 8 GB minimum, 16 if the slot allows.
  9. Reset this PC > Keep my files, when software is the problem and you cannot find it. Reinstalls Windows, keeps documents, removes programs. Back up first anyway.
A machine with an HDD, 4 GB and a trial antivirus is not slow because something is wrong with it. It is slow because that is what it is. Steps 7 and 8 are cheaper than the hours spent on steps 1 to 6, and they last.

Operational notes

  • A full-screen browser window exits with F11, then Esc. If the window persists, identify the owning process in Task Manager (Ctrl+Shift+Esc) and terminate it there. chrome.exe or msedge.exe indicates a web page rather than an installed application, however alarming it looks. Nothing on a web page can "lock" a PC.
  • Session restore reinstates the previous tab set on next launch. Decline it, or clear Continue where you left off in browser settings first.
  • Two resident antivirus products produce scan conflicts, file-lock contention and substantially degraded I/O. Confirm only one is registered under SecurityCenter2.
  • Read-only means read-only: none of the enumeration commands change anything, so run them freely and often. The blocks marked writes changes are the only ones that do.
  • When helping remotely: have them run the snapshot on the Start tab first and send the output. Then decide which tab. Most calls need one tab.
  • Reinstalling the operating system discards the profile, the installed-program history and every persistence artifact. Enumerate before considering it.
